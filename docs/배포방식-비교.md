# 소수 교사 배포 방식 조사 · 2026-11-03

## 권고

소수에게 파일로 나누는 현재 목적에는 **Inno Setup 단일 EXE 설치기 + 사용자 선택형 시작프로그램 바로가기**를 우선 추천합니다. 설치·업데이트·바로가기·제거를 검증된 설치기에 맡기고 기존 C# 인증 로직을 유지하는 방향입니다. 이 항목은 조사 결론이며 Inno 설치기로 전환을 완료했다는 뜻은 아닙니다.

Windows의 StartupTask API를 반드시 사용하려면 **Microsoft Store 배포 MSIX**를 별도 경로로 검토할 수 있습니다. 개인 코드서명 인증서가 없다는 이유만으로 이 경로를 배제할 필요는 없습니다.

## 후보 비교

| 후보 | 확인한 내용 | 현재 목적 판단 |
| --- | --- | --- |
| Inno Setup | 기존 EXE 배포, 사용자별 설치, 설치 체크박스, 바로가기와 제거 프로그램 지원. lowest 권한 설정 가능 | 소수 파일 배포 1순위 |
| Microsoft Store MSIX + StartupTask | Store가 MSIX 서명을 제공. 게시자 등록·본인확인·심사 필요 | StartupTask가 필수이거나 배포 규모가 커질 때 검토 |
| 직접 배포 MSIX | 수신 PC가 신뢰하는 서명 필요. 자체 서명은 추가 신뢰 등록 부담 | 현재 조건에서는 간편 설치가 되기 어려움 |
| Sparse/external-location 패키지 | 기존 설치 경로를 활용해도 신뢰 서명이 필요 | 서명 부재 문제를 해결하는 대안은 아님 |
| Velopack | .NET Framework, GitHub Releases 기반 업데이트, Startup 바로가기 지원. Main 초기화와 실행 경로 통합 필요 | 자동 업데이트가 주요 요구가 되면 검토 |
| ClickOnce | .NET Framework EXE의 서명은 기술적으로 선택 사항이나 인터넷 실사용의 unsigned 배포는 권장하지 않음 | 서명·자동 시작·기존 자기 복사 구조 문제를 단순하게 해결하지 못함 |
| WiX / NSIS | 정상적인 Windows 설치기 대안 | 현재 소규모 설치에는 Inno보다 더 유리한 점을 확인하지 못함 |

## Inno 방식의 실제 변경 범위

- 현재 사용자 계정의 설치 폴더를 사용하고 관리자 권한을 요구하지 않도록 설정합니다.
- 실행 파일·설정 파일을 한 설치 EXE에 넣고 시작 메뉴·바탕화면·프로그램 제거 항목을 제공합니다.
- 자동 시작은 기본적으로 사용자가 직접 선택합니다. 표준 사용자 Startup 폴더의 바로가기에 기존 --auto 동작을 연결할 수 있습니다.
- 기존 도우미의 자동 시작 버튼은 현재 예약 작업 제어이므로 **설치기 체크박스만 바꿔서는 전환되지 않습니다**. 앱의 등록·해제·상태 표시도 새 방식에 맞춰 수정해야 합니다.
- 현재 10초 지연은 예약 작업에 있는 값입니다. 새 방식에서는 도우미가 시작된 뒤 취소 가능한 대기로 옮겨야 하며, Windows 로그온 시각부터 정확히 10초라는 뜻은 달라집니다. 수동 업무 시작은 지연 없이 유지합니다.
- 기존 예약 작업과 새 시작프로그램을 동시에 켜지 않습니다. 새 경로를 검증한 뒤 본인 소유의 기존 등록만 정리합니다.
- Windows에서 사용자가 끈 시작 항목을 앱이 임의로 다시 켜지 않도록 합니다.
- 기존 인증서 선택·암호 입력·확인 1회·공식 SSO는 유지합니다. 설치 파일에 설정·인증서·암호·사용자 로그를 넣지 않습니다.

## Store MSIX를 선택할 경우

MSIX의 **직접 파일 배포**와 **Microsoft Store 배포**는 다릅니다. Store MSIX는 개인 CA 코드서명 인증서를 구입하지 않아도 심사 후 Microsoft가 서명합니다. EXE/MSI를 Store에 등록하는 경로에는 이 MSIX 재서명 혜택을 그대로 적용할 수 없습니다.

새 개발자 등록 흐름은 등록비가 없지만 계정과 본인확인, 앱 심사가 필요합니다. 학교 PC의 Store 허용 여부도 확인해야 합니다. 소수 시험 배포용 Private audience는 개인 Microsoft 계정 목록을 사용하며 학교/직장 계정과는 구분됩니다. 단순 검색 제외·직접 링크 배포는 비공개 접근 제한과 같지 않습니다.

StartupTask는 package identity가 필요합니다. 일반 EXE 설치기에 Windows App SDK를 추가하는 것만으로 대체되는 기능은 아닙니다. StartupTask에는 예약 작업과 같은 10초 지연 속성도 없으므로 앱 내부 대기가 필요합니다.

## 확인 한계와 현재 상태

- 서명 없는 EXE 설치 파일을 만들 수 있다는 사실이 SmartScreen·V3·학교 정책에서 허용된다는 보장은 아닙니다. 차단·경고를 해제하거나 예외를 추가하는 배포 안내는 만들지 않습니다.
- 설치 방식 변경이 인증서 로그인 성공률을 해결한다는 근거는 없습니다. 최신 로그의 K-에듀파인 준비 실패는 별도 안정화 문제입니다.
- 이 문서는 공식 문서·공식 GitHub 조사 결과와 현재 코드 구조를 비교한 설계 판단입니다. Inno/ClickOnce/Velopack/MSIX를 실제로 설치해 비교한 결과는 아닙니다.
- 맞춤 C# 설치 시제품은 구성 요소 무결성·실행 중 차단·구버전 덮어쓰기 차단·임시 설치·사용자 설정 보존 등 23개 검사를 통과했습니다. 검사는 가짜 환경과 임시 테스트 자식 프로세스를 사용했습니다. 실제 Windows UI 시험은 사용자가 Esc로 중단했으며 설치 완료는 검증하지 않았습니다.
- 실제 0.4.12 설치본·인증·예약 작업은 이번 조사에서 전환하지 않았습니다. 새로운 코드서명 인증서 설치나 보안 설정 변경도 하지 않았습니다.

## 구현 및 한계

- 검출과 대기 정책을 분리하고 Loading / Clear / Unknown을 사용한다.
- 보안 대기는 협력적 polling 250ms, Clear 안정화 1000ms, 작업당 누적 상한 120000ms다.
  후보 기본값이며 콜드 부팅의 최대 시간으로 실증된 수치는 아니다.
- 기존 단계 제한에서는 명시적 보안 대기 경과 시간을 제외한다. 중단 확인은 계속한다.
- 화면 캡처는 검증한 업무포털 문서 영역으로 한정하며 디스크에 기록하지 않는다.
  최소화, 화면 밖, 가림, 문서 소유권 불일치, 캡처 오류는 Clear로 처리하지 않는다.
- 이미지 기준 효과 배율 50~300%를 비교한다. 단위 테스트에는 137%도 포함했다.
  기준 이미지 변경, 극단적 배율, 브라우저 이미지 변형 등은 일반화해 보장하지 않는다.
  UIA의 가운데 익명 이미지 그룹이 남아 있으면 매칭 실패는 Unknown이다.
- 이미지가 나타날 수 있는 문서 중앙 영역만 캡처하고, 진행 안내는 그 밖으로 이동해
  계속 표시한다. 공간이 없으면 한 번 숨긴 뒤 트레이·단축키 중단을 유지한다.
  검사마다 숨김·표시하지 않는다. 외부 창이 캡처 영역을 가리면 사용자가 보여 줄 때까지 기다린다.
- 대기 후 fresh Locate/Validate를 수행한다. 입력 중에는 긴 대기를 하지 않고 즉시 중단한다.
- 직접 입력, legacy 키보드, 별도 진단 입력 경로에 최종 검증을 적용한다.
  SubmitOnce 전에 검사하고 callback에서는 기다리지 않고 현재 확인 버튼을 재조회한다.
  PendingAttempt와 1회 제출/중단 순서는 그대로 유지한다.
- Loading 및 Unknown은 빈 화면 새로고침의 안전 조건을 충족하지 않는다.

`test.ps1`: 398개 회귀 검사 통과. 가짜 시계·검출기로 최초 로딩, 준비 중 출현,

## 사용자 시험 후 수정

진행창의 polling마다 Hide/Show하던 동작이 깜빡임을 발생시켜 제거했다.
중앙 캡처 영역 밖에 안내를 고정하고, 실제 화면에 저장할 수 있는 공간이 없을 때만
한 번 숨긴다. 등록 중 브라우저의 매체를 선택할 때는 등록 도우미를 한 번 숨겼다가
완료 후 복원한다. 로컬 암호 저장 대화상자가 열린 뒤에는 UIA로 문서·저장 위치·인증서
동일성을 재검증하며, 그 대화상자가 브라우저를 가린다는 이유로 로컬 저장을 막지 않는다.

사용자가 명시적으로 인증서를 재등록할 때는 이전 PendingAttempt로 등록을 차단하지 않는다.
새 자격 증명과 메타데이터 저장이 성공한 시점에만 PendingAttempt를 해제한다.
취소·검증 실패·저장 실패에서는 이전 상태를 유지한다. 자동 로그인에서는 여전히
미확인 시도의 재입력·재제출을 막는다. 등록 성공·실패·취소, 진행창 반복 관찰 시
Visibility 전환 없음, 중앙 영역 캡처의 배율별 검출을 회귀 검사에 추가했다.

16:36 사용자 시도 로그에는 DIRECT_ELEMENT_INPUT_STARTED 뒤 제출/성공 없이
AUTHENTICATION 단계 NullReferenceException이 기록돼 있었다. 인증서 모달이 사라졌을 때
null 요소를 그대로 조회하던 경로를 명시적인 중단으로 보강했다. 기존 로그에 stack은
없으므로 이것을 해당 예외의 확정적인 발생 위치라고 단정하지 않는다.

정상 화면에서는 보안 확인 안내와 추가 1초 대기를 반복하지 않는다. 첫 관찰이 Clear이면 바로 진행하고, Loading/Unknown이 실제 관찰될 때만 제한된 대기와 해제 안정화를 시작한다. 입력·제출 직전 즉시 안전 검사는 유지한다. 정상 10단계 및 로딩 해제 이후 대기·메시지 반복 없음 검사를 추가했다.

성능 최적화: 정상 문서의 UIA 트리에 중앙 익명 350×187 그룹이 없으면 화면 캡처와 배율 비교를 건너뛴다. 실제 보안 안내가 보일 때만 캡처 기반 검사를 수행하므로 인증서창이 이미 준비된 뒤 반복 지연이 발생하지 않는다.

인증서 목록은 동일한 사용자·만료일·발급자 조합의 중복 행을 하나의 논리 인증서로 묶는다. 동일 정보의 하드디스크 중복이면 선택된 행을 우선하고 암호 입력 단계까지 진행할 수 있다. 서로 다른 인증서 정보가 여러 개면 기존처럼 임의 선택하지 않고 중단한다. 실제 암호 입력·제출은 시험하지 않았다.
